# Оптимизация входного контроля методом Монте-Карло

**Цель работы:** Изучение эффективности применения метода Монте-Карло для поддержки принятия решений в производственно-экономических задачах[cite: 3].

## Описание задачи

На предприятие радиоэлектронной промышленности поступают комплектующие изделия – резисторы с номиналом невысокой точности (15%)[cite: 3]. Известно, что определенная часть резисторов не подходит для изготовления продукции и требует дополнительной подгонки[cite: 3]. Чтобы выявить бракованные детали до сборки, необходим входной контроль, который требует финансовых затрат[cite: 3]. Если бракованный резистор устанавливается в изделие без контроля, стоимость его последующей замены значительно возрастает[cite: 3]. 

**Задача:** Найти, какую часть резисторов необходимо подвергнуть входному контролю, чтобы общие затраты предприятия на контроль и подгонку были минимальными[cite: 3]. Псевдослучайные числа для моделирования формируются на основе сдвигового регистра с линейной обратной связью (LFSR)[cite: 3].

## Исходные данные (Вариант 14)

В соответствии с индивидуальным вариантом №14 используются следующие параметры моделирования[cite: 3]:
* **Доля бракованных резисторов (A):** 17%[cite: 3]
* **Стоимость контроля одного резистора (B):** 7 руб.[cite: 3]
* **Стоимость подгонки детали (C):** 65 руб.[cite: 3]
* **Стоимость замены детали в изделии (D):** 85 руб.[cite: 3]
* **Генератор ПСЧ:** 32-битный LFSR на базе неприводимого полинома №1[cite: 3].
* **Полином:** $X^{32}+X^{28}+X^{22}+X^{21}+X^{20}+X^{19}+X^{18}+X^{16}+X^{10}+X^8+X^7+X^3+1$[cite: 3].

## Архитектура программного комплекса

Приложение разработано на языке Python с использованием модульной многофайловой архитектуры, разделяющей бизнес-логику и пользовательский интерфейс:

1. **`lfsr.py` (Генератор псевдослучайных чисел)**
   Модуль реализует класс 32-битного генератора псевдослучайных чисел по схеме LFSR. Битовые сдвиги и операции XOR настроены строго в соответствии со степенями заданного полинома. Генератор возвращает равномерно распределенные числа с плавающей точкой в диапазоне [0, 1) для имитации вероятностных событий в системе.

2. **`monte_carlo.py` (Бизнес-логика и моделирование)**
   Ядро математической модели. Содержит функцию `run_simulation`, которая принимает экономические параметры предприятия и количество итераций (испытаний). Процесс моделирует проверку партий комплектующих при различном проценте входного контроля (от 0% до 100% с шагом 5%) и возвращает массив рассчитанных финансовых издержек для каждого сценария.

3. **`app.py` (Графический интерфейс пользователя - GUI)**
   Современное графическое приложение, построенное на базе библиотеки **CustomTkinter**. Интерфейс предоставляет пользователю удобные поля для ввода исходных параметров. Результаты расчетов выводятся в двух форматах через систему вкладок:
   * **Таблица результатов:** Показывает точные значения затрат для каждого процента покрытия контролем, выделяя оптимальную стратегию зеленым цветом.
   * **Визуализация (Matplotlib):** Интегрированный в интерфейс интерактивный график зависимости общих затрат от доли контролируемых партий. Минимум функции (оптимальная точка) автоматически рассчитывается и выделяется на графике красным маркером для быстрого принятия решений.
